# Fast path (written for the model; terse on purpose)

MAIN = G1, G4, joins. Never read code, test logs or kit source in main. Never edit code or run formatters in main: an edit after `complete implement` reruns every check; a style nit is a note. Read only CLI JSON, subagent summaries, `git diff --stat`. CLI = `node .ai-workflow/bin/graph.mjs`; its JSON is compact, never tail it. Pipe other long output through `| tail -20`. Never sleep or poll: subagent results arrive by themselves. Chain dependent CLI calls with `&&` in one Bash call. No subagents on this host: do steps 1, 3 and 4 in main, same order.

1. STORY: one Agent `model: opus` (scope is where a strong tier pays) gets the request and these rules. It explores first (at most 12 tool calls: code path and callers, tests, config, external contracts), writes `docs/stories/<slug>.md` from `../assets/STORY.md`, and returns at most 10 lines (Goal, MUST titles, ASSUMED, OUT) plus a map of at most 15 lines (`file:line` refs, current behavior, test command):
   - Goal: `1. As-is:` `2. To-be:` `3. Unchanged:`. To-be removes the pain the request describes, including manual or night-time operational work it mentions; never put what that needs into OUT (make it MUST, or `OPEN BLOCKING`). Whoever drafts the Story first runs `graph.mjs copies <files or folders the change touches>` and follows its `rule`: parallel copies the request does not name are all in To-be, never ASSUMED one copy into OUT; D1 is `Copies:` the list and the decision. Domain: numbered Terms, Invariant.
   - Decisions above MUST: `ASSUMED` defaults; `OPEN BLOCKING` only for behavior a human must choose (money, migration, auth: never `ASSUMED`; see `domain-risks.md`).
   - MUST/SHOULD/OUT: title line, nested numbers; results that happen together on one line joined by `+`.
   - Verify: `V# [M#]` success and failure.
   - Footer after `---`: Status, Owner, `Lane: light` only if reversible + one module + no external contract + no persistent data + not high-risk; else `Lane: standard`.
   - At most three blocking questions, two rounds. Open idea or more questions: `intake.md`.
2. G1: show the Story path and its Decisions lines, then explain in the user's language, at most five lines (today, after, unchanged, how we check). Ask. END THE TURN. Only an explicit approval counts. Then, in one message, one Bash call: save the reply with a heredoc to `.ai-workflow/approvals/<slug>-g1-reply.md` `&& graph.mjs approve G1 <story> --response <reply> && graph.mjs go <story> .ai-workflow/runs/<slug>.json --scope <module or path>…` (light lane: `light` instead of `go`). Never edit Status or gate lines yourself. The brief's `checks` are the exact commands; never open `verification.json`.
3. IMPLEMENT: one Agent, `model: sonnet`. Give it the Story MUST and Verify, the brief JSON, the run path and the map. Its rules: test-first; one focused test per Verify item, a second only for a distinct failure path; run a new test RED once only when it compiles against existing code; never the full suite; never write a test runner; if tests cannot run here, say so. It finishes with `graph.mjs complete <run> implement --tests <its test classes or files and the existing tests of classes it changed>` (light: `graph.mjs check <run> --tests …`): that is its GREEN run. On `status: failed` it fixes from `failing.tail` and runs `complete` again, at most twice; a failure only in an untouched test existed before: drop it from `--tests` and say so. It returns at most 15 lines: files, `V# → test` for every Verify item, the last `complete` JSON.
4. REVIEW: one Agent `model: sonnet`, read-only (no builds or test runs; at most 8 tool calls). Give it the Story path, the implementer's report and `<slug>`. It reads `git diff`, writes findings to `.ai-workflow/evidence/review-1.md` (at most 15 lines) and, on pass, four Korean lines to `.ai-workflow/approvals/<slug>-g4-summary.md`: `1. 사용자가 겪는 변화` `2. 지킨 규칙과 실패할 때 동작` `3. 확인한 테스트` `4. 확인하지 못한 것`. Verdict `fix` only when a MUST or Verify item is unmet or behavior is wrong; anything else is a note.
   - Pass: one Bash call: `graph.mjs complete <run> workflow-review --verdict pass --notes .ai-workflow/evidence/review-1.md && graph.mjs complete <run> workflow-verify && cat <summary>`. Light: `graph.mjs review <run> --verdict pass --notes … && cat <summary>`.
   - Fix: `--verdict fix` alone; the implementer fixes only the listed findings and runs `complete implement`; then the pass call without a new reviewer (one round); main writes the summary, and anything not fixed goes to line 4.
   - Implement still failing after two attempts: implement again with `model: opus`.
5. VERIFY reuses passing receipts; expect `next: g4`. Light: no verify step.
6. G4: show the four lines as written. Ask. END THE TURN. Only an explicit approval counts; on a correction, fix the line and ask again. Then one Bash call: save the reply to `.ai-workflow/approvals/<slug>-g4-reply.md` `&& graph.mjs approve G4 <run> --summary <summary> --response <reply>`. Report its result.

Other cases: `next: human|replan` → ask the human. `stop` → report, no new run. High-risk (G3) or several dependent outcomes → `execution.md`. Roles → `role-graphs.md`.

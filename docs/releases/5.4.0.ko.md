# 5.4.0 — 2026-11-24

한국어 · [English](5.4.0.md)

이번 릴리스는 비용과 시간을 줄이는 데 맞췄습니다. 실제 작업에서 순정 Claude Code 세션과 비교하며 조정했고, 결과는 [EVALUATION.md](../EVALUATION.md)(영문)에 있습니다.

- **작은 변경을 바로 처리하는 길.** 요청이 동작 하나와 그 위치를 말하고, 정할 것이 없고(평행 복사본 없음, 가정하거나 물을 것 없음), 되돌릴 수 있고, 한 모듈 안이며, 외부 계약·영속 데이터·고위험 영역을 건드리지 않으면, 에이전트가 바로 고치고 말한 동작마다 테스트를 하나씩 더해 돌린 뒤 보고합니다. Story, G1·G4, 서브에이전트가 없습니다. 정할 것이 남으면 일반 경로로 갑니다.
- **더 짧은 일반 경로** (`skills/workflow/references/fast-path.md`): 상위 모델 서브에이전트가 코드를 살펴 Story를 쓰고, 중간 모델 서브에이전트가 구현과 검사를 하고, 읽기 전용 중간 모델 서브에이전트가 한 번 리뷰합니다.
- **기록은 그래프 CLI가 맡습니다.** `approve G1|G4`는 사람의 답을 저장한 파일로 승인 기록을 씁니다. `go`는 승인된 Story를 첫 작업 지시로 바꿉니다. `complete`는 작업의 검사를 돌려 결과를 기록하고 다음 작업을 시작합니다. `profile`은 `package.json`, `tsconfig.json`, `gradlew`에서 검사 설정을 만듭니다. 같은 코드에서 통과한 검사는 다시 돌리지 않고 재사용합니다.
- **가벼운 경로(light lane):** Story는 필요하지만 작고 되돌릴 수 있는 한 모듈 작업은 전체 그래프 실행 없이 `light`, `check`, `review`, `delivery`로 끝냅니다. Story 꼬리말에 `Lane: light`가 붙습니다.
- **`graph.mjs copies <파일 또는 폴더>...`** 는 변경이 닿는 코드의 평행 복사본을 나열합니다. 예를 들어 형제 브랜드·플랫폼·언어 폴더에 있는 같은 컴포넌트입니다. Story를 쓰는 쪽이 먼저 실행하고, 요청이 코드에서 쓰는 이름으로 특정 복사본을 지목하지 않으면 Story는 모든 복사본을 다룹니다.
- **이름을 지정한 Gradle 테스트를 그 테스트가 있는 모듈에서 돌립니다** (`:a:test --tests A :b:test --tests B`). 예전에는 여러 태스크 뒤에 `--tests` 목록 하나를 붙여, 첫 모듈의 테스트를 전부 돌리고 마지막 모듈은 "No tests found"로 실패했습니다.
- **Story 양식 v2:** Goal은 세 줄(As-is, To-be, Unchanged), Decisions가 MUST 앞에 오고, `Status`, `Owner`와 게이트 줄은 Verify 아래 꼬리말에 둡니다. 검사기는 5.3.0 순서도 계속 받습니다.
- **G4 기본값은 AI 요약입니다.** 번호 붙은 네 줄을 사람이 명시적으로 승인합니다. G3 결정이 있는 Story는 계속 `human-restatement`를 씁니다.
- **리뷰어는 기본 한 명,** G3 Story는 두 명입니다.

5.3.0에서 올릴 때: 역할 그래프와 실행 형식이 바뀌지 않아 5.3.0에서 시작한 실행이 그대로 이어집니다. `init`으로 관리되는 `AGENTS.md`·`CLAUDE.md` 블록과 스킬을 갱신한 뒤 새 세션을 여세요.

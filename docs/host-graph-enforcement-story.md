# 호스트 그래프 연결 검토 — 구현 범위 축소

2026-09-22. 비판·중재 에이전트 2개의 사전 검토 결과다. 이전의 강제 적용 Story 초안을 대체한다. 새로운 호스트 권한 체계나 Office 연결을 승인·구현한 기록이 아니다.

## 결론

현재 그래프를 크게 확장할 근거는 부족하다. kit는 업무 규칙을 제공하고 호스트는 실행과 권한을 관리한다. Office에서 여러 개발자를 실행할 때도 이 경계를 유지한다.

## 지금 반영할 것

- G1 checker가 검사하는 것은 승인 기록과 파일이다. 실제 사용자의 승인을 받았는지 확인하는 책임은 호스트에 있다.
- 범용 그래프 API와 delivery CLI의 보장을 구분한다. 범용 API는 시도 수를 세지만 상한을 강제하지 않고, human/replan 실패 후 독립 작업을 계속할 수 있다.
- 현재 설치는 지침·체커·그래프 CLI를 제공한다. 호스트 도구를 차단하거나 승인 기록의 변조를 막는 기능을 설치하지 않는다.

## 유지할 것

- 의존성 기반 실행과 join, 명시적인 read 작업 병렬화, 같은 실행의 writer 배타 정책.
- 늦은 결과를 구분하는 작업 토큰, 증거 변경 검사, 영향을 받는 후속 작업 reset, 파일 잠금과 원자적 교체.
- G1/G3/G4, 작은 작업의 최소 계획, 필요한 단계에만 적용하는 Superpowers와 CE, 검증 후 Compound.
- read는 제품 코드 수정 금지다. 증거 기록과 테스트 생성물의 쓰기까지 일괄 금지한다는 뜻이 아니다.

## 추가하지 않을 것

- kit 자체 worktree 관리자, 병렬 개발 엔진, 메시지 시스템, 권한 broker.
- 고정된 개발자·리뷰어 팀, 별도 join 에이전트, 필수 planning graph 절차.
- Jev, ADK SDK, 새 서버, 모델 provider.

## 실제 Office 연결 시 확인할 것

Office 담당 세션은 실제 저장·실행 경로에서 아래를 확인한다. 이 문서는 Office에 이미 구현되었다고 보증하지 않는다.

1. 한 곳의 권위 있는 상태와 원자적 작업 예약.
2. 독립 작업 공간 또는 충돌하는 코드 수정의 직렬화.
3. 취소·중복·늦은 결과를 처리하는 기준과 실제 프로세스 정지.
4. 코드 통합과 통합된 변경본의 최신 검증.
5. 실제 사용자의 승인 이벤트와 승인 대상 변경본.

그 과정에서 kit에 필요한 입력, 기대 결과, 실패 사례가 확인되면 CLI와 공유할 최소 전이 함수를 추출한다. 현재 CLI 내부에는 이를 위해 제거해야 할 중복이 없으므로, 소비자가 없는 내부 리팩터링이나 새 공개 API는 먼저 만들지 않는다.

## 강제 적용의 검증 경계

호스트 연결을 강제 적용이라고 부르려면 실제 도구 경로에서 예약 없는 작업, 읽기 전용 작업의 제품 수정, 만료된 결과를 거부하는지 확인해야 한다. 에이전트가 상태·승인·검사 설정을 직접 바꾸는 우회도 확인해야 한다. 이 격리와 권한 통제는 호스트의 책임이다. kit의 로컬 파일 검사나 hook의 존재만으로 검증됐다고 표시하지 않는다.

호스트별 차단 기능과 Office의 실제 연결은 이번 검토에서 검증하지 않았다. 새로운 보안 경계가 필요하면 기존 승인 범위를 먼저 확인한다. 이 세션은 Office 저장소를 수정하지 않는다.
